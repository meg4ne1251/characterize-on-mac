# 要件と検証方針

## 確定している方針

- macOS 上で動作すること。
- Autodesk FBX SDK を使用すること。
- Maya のインストール・ライセンスに依存しないこと。
- MotionBuilder で行っているキャラクタライズ作業を対象とすること。
- GitHub の private リポジトリで管理すること。

## 資料をもとに確認すること

- 現在の作業手順と、既存スクリプトが担当している処理。
- 「キャラクタライズ完了」と判断する条件。たとえば、ボーンの対応付け、キャラクタ定義の保存、その他の設定のうち、どこまで必要か。
- 入力 FBX の構成、ボーンの命名規則、基準ポーズ、座標系・単位。
- 出力 FBX を利用するアプリケーションと、そこで再現する必要がある状態。
- 複数キャラクタ、欠損ボーン、命名の違いなどの扱い。

## 技術検証で決めること

- FBX SDK で読み書きできる情報と、MotionBuilder 固有の処理に相当する部分の実現方法。
- 採用する SDK バージョンと、対応する macOS・CPU アーキテクチャ。
- 実装言語と SDK の利用方法。
- 実行方法（スクリプト、CLI、必要に応じて UI）。

FBX SDK の利用だけで目的の状態を再現できるかは、まだ検証していません。

## 進め方

1. 関連資料と MotionBuilder スクリプトを集め、現在の入出力と処理手順を整理する。
2. 最小限の検証用 FBX と、期待する出力・確認手順を用意する。
3. macOS 上で FBX SDK の導入と、読み込み・保存を検証する。
4. 必要なキャラクタライズ処理を実装し、期待する結果と比較する。
5. 実行手順、制約、検証結果を文書化する。

## 完了条件のたたき台

- 対象の macOS 環境で Maya に依存せず実行できる。
- 合意したサンプルに対し、必要な設定を含む FBX を出力できる。
- 出力先のアプリケーションで、期待するキャラクタ状態になっていることを確認できる。
- 入力に不足や非対応の構成がある場合、理由を確認できる。

具体的なサンプルと合否基準は、資料の確認後に決めます。
