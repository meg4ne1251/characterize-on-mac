# コードレビューと修正（2026-10-28）

対象は `src/characterize/`、ビルド・SDK準備・実モデル検証スクリプト、既存テストです。入力保護、画像参照と保存、ポーズ補正の境界値、CLI の終了判定を確認しました。

## 修正した問題

| 優先度 | 問題と影響 | 修正 |
| --- | --- | --- |
| 高 | レポートの固定名一時ファイル `<report>.tmp` が入力 FBX へのシンボリックリンクの場合、`inspect` だけで入力を JSON に書き換える | 排他的に作成した固有の一時ファイルへ保存し、成功後に置換。失敗時は一時ファイルを削除 |
| 高 | `--force` と出力先の指定次第で、`--texture-reference` の参照 FBX を FBX やレポートで上書きできる | 参照 FBX も入力と同じく上書きを拒否 |
| 中 | `.assets` に同名ファイルがあると内容を検査せず再利用し、破損した画像でも成功扱いになる | 内容を照合し、不一致なら一時ファイル経由で置換。シンボリックリンクの参照先は変更しない |
| 中 | 同じパスの参照 FBX を差し替えると、以前の埋め込み画像がキャッシュから再利用され、欠落画像を見逃す | CLI のすべての読み込みで新しい画像展開ディレクトリを使用 |
| 中 | 画像の読み込みと存在検査で探索方法が異なり、元のパスが無効でも展開先から取得できる画像を「なし」と判定する。また、展開済みの直接参照より外部画像を先に使う | 共通の `textureFile()` で解決し、展開先を直接指す参照を優先。同名の別画像を誤用しないよう、ファイル名のみでの探索は最後に行う |
| 中 | 非一様スケールの許容差に下限 `1.0` を使うため、`(0.01, 0.01005, 0.01)` のような 0.5% の差でも安全性検査を通過する | スケールの最大値に対する相対 `1e-4` で判定。微小な浮動小数点誤差は引き続き許容 |
| 中 | NaN・無限大を含むボーン座標が、角度比較をすり抜けてポーズ検査に合格する | 有限値の検査と `pose.nonfinite` エラーを追加。補正中の角度判定でも不正値を拒否 |
| 中 | モデル検証スクリプトを別ディレクトリから相対パスで起動すると、子プロセスがプロジェクト直下の別パスを読み込む | 入力・参照・出力を呼び出し元基準の絶対パスへ変換 |

加えて、`--allow-check-errors` で保存後の検査不合格を許可した分岐でも、全体の結果・終了コードを不合格として返すようにしました。

主な変更箇所は [main.cpp](../src/characterize/main.cpp)、[media.cpp](../src/characterize/media.cpp)、[scene.cpp](../src/characterize/scene.cpp)、[tpose.cpp](../src/characterize/tpose.cpp)、[validate_models.py](../scripts/validate_models.py) です。

## 再現・回帰テスト

- [CLI テスト](../tests/test_cli.py): 入力保護、参照 FBX の保護、破損した同梱画像の修復、古いキャッシュの排除を追加。修正前のソースから作成したバイナリでは追加した4件が失敗し、修正後は合格。
- [ネイティブテスト](../tests/review.h): 展開済み画像の別名解決と参照の優先順位、小さいスケール、NaN・無限大の検査を追加。
- [スクリプトテスト](../tests/test_scripts.py): 別ディレクトリから相対パスで実行し、モデルの処理とデータ保持検査まで確認。

## 検証

- CLI・テスト用バイナリのビルド成功。
- ネイティブテスト: 256項目に合格。
- Python 統合テスト: 27件に合格。

実モデル5件を、通常設定と `--flat-shader` の2通りで検証しました。

| モデル | 通常設定 | Flat 設定 | 結果 |
| --- | --- | --- | --- |
| Chis-A | 合格 | 合格 | 画像埋め込み・保存後の検査・データ保持監査に合格 |
| Gakupo | 合格 | 合格 | 同上 |
| Rakuteni | 合格 | 合格 | 同上 |
| GUMI | 出力停止 | 出力停止 | テクスチャが指定する UV 名 `default` が対象メッシュにない（`check.texture_uv`） |
| kiritan | 出力停止 | 出力停止 | 保持対象の旧テクスチャ86件の元画像がない（`texture.embed_source`） |

すべての入力 FBX で、処理前後の SHA-256 が一致しました。成功した3件では各設定で合計186,949頂点、158シェイプターゲット、295,878ウェイトなどを照合しました。詳細レポートは `tmp/review-validation/default/reports/` と `tmp/review-validation/flat/reports/` にあります。

GUMI と kiritan は修正前のコードでも同じエラー種別・件数で停止することを確認しました。今回の変更による回帰ではありません。UV の割り当てや欠落画像の扱いは、元データを確認して別途指定する必要があります。

MotionBuilder の HIK ソルバと実画面での確認は、この SDK 上の検証の対象外です。
