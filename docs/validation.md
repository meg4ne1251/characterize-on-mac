# 検証結果（2026-10-27）

## 環境

macOS 27.0.1 / Apple Silicon arm64 / FBX C++ SDK 2020.3.11。Maya・MotionBuilder は実行せず、独立した C++ ツールとして確認しました。

## 提供モデルによる検証

以下は `python3 scripts/validate_models.py --force` の結果です。処理前モデルから出力し、対応する `_MB` がある4件では画像を参照しました。GUMI は入力の画像接続を使いました。

| モデル | 結果 | リンク数 | 最大軸ずれ（度） | 照合した頂点 | シェイプターゲット | ウェイト数 |
|---|---|---:|---:|---:|---:|---:|
| Chis-A.fbx | 合格 | 50 | 0.0001207 | 82,270 | 56 | 161,094 |
| GUMI.fbx | 合格 | 52 | 0.0007537 | 77,011 | 102 | 108,208 |
| Gakupo.fbx | 合格 | 52 | 0.0003792 | 37,691 | 54 | 47,305 |

全5件で、入力の SHA-256 が処理前後で一致し、FBX を保存して開き直した検査にも合格しました。対応する `_MB` がある4件では、参照 Character にあったスロットの欠落はありませんでした。Kiritan の旧 InHand 名は現行名へ正規化しています。

データ保持の照合では、メッシュ・ノード数、元の頂点座標、ポリゴンの接続、UV、法線、マテリアルスロット、シェイプターゲット、スキン接続、ウェイト、バインド行列を確認しています。腕・脚のボーン長も照合し、最大相対誤差は `5.76e-9` 未満でした。これはポーズ変更前後の基礎データの保持を検査するもので、全モデルの見た目・リターゲットの品質まで保証するものではありません。

出力は `data/output/*_mac.fbx` と対応する `.assets/`、詳細 JSON は `data/output/reports/` にあります。いずれも Git 対象外です。

## 自動テスト

- ネイティブテスト: **174 assertions 合格**。73スロットすべての SDK 識別子、マッピング、A→T補正、スキン変形の追従、頂点・バインド保持、保存後の再読み込み、再補正、pre/post rotation、旧名、改名衝突、重複シェイプ、不正スケール、アニメーション拒否を検証。
- CLI 結合テスト: **12件合格**。入力不変、出力の検査、JSON、再改名、既存 Character・既存出力の保護、不正な名前・角度、画像の曖昧さ、アニメーションを検証。

## 表示・互換性の確認状況

FBX Review 1.5.4 で `Gakupo_mac.fbx` を読み込み、ソリッド表示でメッシュの腕が水平なTポーズになることを確認しました。全モデルのテクスチャ表示、肩・手首・指・足裏・衣服の見た目については、追加の目視確認が必要です。

MotionBuilder の実行環境では確認していません。HIK の有効化、リターゲット、MotionBuilder 固有のグループやシェーダーとの完全互換は未確認であり、レポートでも `motionbuilder_verified: false` を維持します。SDK の再読み込みが通ったことを HIK の検証成功とは扱いません。

参照 `_MB` にも脚の傾きや複数 Character があるため、ファイル全体の一致を合格条件にはしていません。詳細は [提供資料の解析](source-analysis.md) を参照してください。
